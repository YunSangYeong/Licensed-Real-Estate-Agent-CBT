### 모바일 메뉴 입력 증거

390×480과 740×360에서 메뉴 애니메이션 완료 후 다음 순서를 PC/모바일 프로필 모두 실행했다.

1. 메뉴의 실제 높이보다 콘텐츠가 길어 내부 overflow가 있는지 확인.
2. `page.mouse.wheel`로 아래 이동, 읽기 전용 scrollTop 증가 및 백업 버튼의 뷰포트 진입 확인.
3. 백업을 실제 클릭하여 JSON 다운로드 파일명 확인.
4. 반대 휠로 위 이동, scrollTop 0 및 상단 대시보드 접근 확인.
5. CDP `Input.dispatchTouchEvent`의 touchStart/move/end를 연속 입력하여 위로 스와이프, 아래 도구 접근 확인.
6. 하단 초기화 버튼을 실제 클릭하고 확인창 취소.
7. 반대 터치 스와이프로 상단 복귀, 대시보드가 뷰포트 안에 있고 실제 선택되어 메뉴가 닫히는지 확인.
8. 별도 검사에서 메뉴 글자 24px 확대 후 하단·상단 휠 접근 확인.

검사에서 scrollTop을 설정하는 코드는 없으며 DOM 존재만으로 통과시키지 않는다. Chromium 모바일 에뮬레이션의 신뢰된 입력을 사용한 결과다. 물리적 휴대전화·iOS Safari·주소창이 동적으로 바뀌는 실제 기기 동작은 미실행이다.
