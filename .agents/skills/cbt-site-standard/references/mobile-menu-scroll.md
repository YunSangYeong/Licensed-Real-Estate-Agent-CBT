# 모바일 메뉴 스크롤 회귀 검증

## 확인된 원인과 필수 구현

ForkLift-cbt에서 fixed 사이드바에 내부 세로 overflow가 없어 작은 화면에서 메뉴 하단이 뷰포트 밖으로 잘리고 위·아래 스크롤이 되지 않는 문제가 발생했다. 메뉴는 고정하되 콘텐츠 전체가 독립된 세로 스크롤 영역에 포함돼야 한다.

기준 앱 커밋에도 이 수정이 들어 있다고 가정하지 말고 재사용할 때 적용한다. 아래는 요구를 충족하는 CSS 예시이며 실제 구조·브라우저에서 동작을 검증해야 한다.

```css
.sidebar {
  position: fixed;
  inset: 0 auto 0 0;
  display: flex;
  flex-direction: column;
  max-height: 100vh;
  max-height: 100dvh;
  overflow-y: auto;
  overscroll-behavior-y: contain;
  -webkit-overflow-scrolling: touch;
}
.sidebar > * { flex-shrink: 0; }
```

전체 메뉴를 스크롤하는 구조와 메뉴 본문만 스크롤하는 구조 모두 가능하다. 어느 경우든 브랜드·상단 대시보드·모든 내비게이션·하단 도구가 접근 가능해야 한다. 키보드 포커스와 메뉴 닫기, 화면 회전, 배경 스크롤 처리도 유지한다. `touch-action: none`, 전역 `touchmove.preventDefault()` 등으로 메뉴 터치 스크롤을 차단하지 않는다.

## 필수 검사 순서

1. **작은 높이**: 390×480 CSS 픽셀에서 메뉴를 열고 애니메이션 완료를 기다린다. 콘텐츠가 메뉴보다 길 때 실제 스크롤 영역이 형성되는지 확인한다.
2. **아래 이동**: 메뉴 안에서 휠 또는 터치 스와이프로 내려 `scrollTop > 0` 및 하단 백업·초기화 버튼의 뷰포트 진입을 확인한다. 페이지 배경만 움직이는 것은 실패다.
3. **위 이동**: 반대 방향 입력으로 메뉴 처음까지 돌아와 대시보드 버튼이 뷰포트에 보이고 선택 가능한지 확인한다.
4. **터치 별도 확인**: 터치 가능한 모바일 에뮬레이션에서 실제 touchStart/move/end 또는 지원되는 스와이프를 입력한다. 휠 테스트를 터치 검증으로 보고하지 않는다. 메뉴 전환 중의 잘못된 좌표를 피하도록 애니메이션 종료를 기다린다.
5. **화면 변화**: 일반 세로 화면과 740×360 등 짧은 가로 화면, 확대된 글자에서도 항목 접근성을 확인한다. 주소창/뷰포트 높이 변화가 메뉴를 가리거나 불필요한 가로 넘침을 만들지 않는지 확인한다.
6. **회귀**: 메뉴 열기·닫기, 항목 선택 후 닫기, 배경 오조작 방지, 키보드 포커스·Space 보호를 확인한다. 스크롤 가능한 메뉴가 긴 데스크톱/작은 창에서도 잘리지 않는지 확인한다.

자동 회귀 검사는 작은 높이의 아래/위 이동과 하단/상단 뷰포트 접근을 포함한다. `element.scrollTop = ...` 같은 프로그램적 이동만으로 스크롤 입력 성공을 대신하지 않는다. 자동·수동, 휠·터치, 에뮬레이션·실기기 결과를 구별한다. 실기기·특정 브라우저에서 실행하지 않은 검사는 미실행으로 기록하며 오류가 다시는 없다고 보증하지 않는다.

배포는 SKILL.md v1.4.0의 요청받은 에이전트 진행·첫 차단 시 중단 정책을 따른다. 이 검증 문서만 바꿨다는 이유로 배포·재배포를 실행하지 않는다.
